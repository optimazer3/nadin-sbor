# Бот задач для руководителя

Telegram-бот, в который руководитель записывает задачи для команды **голосом**. Бот сделан
максимально простым: без смайликов, без статистики и подсказок — только список задач
и голосовое управление.

- **Сказал — бот сделал.** Руководитель нажимает микрофон и говорит: «Ивану подготовить отчёт
  до пятницы», «задача 5 выполнена», «перенеси задачу 5 на понедельник», «удали задачу 3».
  Бот распознаёт речь (AssemblyAI), понимает команду (нейросеть через Polza AI) и коротко
  переспрашивает: «Добавить задачу?», «Отметить задачу 5 выполненной?». Ответить можно голосом —
  «да» или «нет» — или кнопкой. После «да» бот пишет «Готово.» и присылает обновлённый список.
- **Список задач на контроле** — номер, задача, под ней исполнитель и срок (только если они есть).
  Задачи разделены пустой строкой, номера идут по порядку: 1, 2, 3…
- **Раз в неделю** (по умолчанию в понедельник в 10:00) бот сам присылает этот список. День и время
  можно поменять голосом: «присылай список по пятницам в 9 утра».
- Внизу экрана одна кнопка — «Список задач».

Пример списка:

```
Задачи на контроле

1. Подготовить отчёт по продажам
Иван Петров, до 13 ноября

2. Обновить прайс
Мария Сидорова

3. Заказать воду
```

Выполненные и отменённые задачи из списка уходят (их можно посмотреть: «покажи выполненные»).

## Запуск на своём компьютере: пошаговая инструкция

Понадобятся пять ключей и адресов. Записывайте их по ходу в блокнот, в конце они пойдут в файл `.env`:

| Что | Куда пойдёт |
|---|---|
| токен Telegram-бота | `BOT_TOKEN` |
| адрес проекта Supabase | `SUPABASE_URL` |
| секретный ключ Supabase (service_role) | `SUPABASE_KEY` |
| ключ AssemblyAI | `ASSEMBLYAI_API_KEY` |
| ключ Polza AI и ID модели | `LLM_API_KEY`, `LLM_MODEL` |

### Шаг 1. Установите Python

Нужен Python **3.11 или новее**. Скачайте его с [python.org/downloads](https://www.python.org/downloads/).

- **Windows:** в первом окне установщика обязательно поставьте галочку **«Add python.exe to PATH»**.
- **macOS:** установите пакет с сайта или через Homebrew (`brew install python`).

Проверьте в терминале (Windows: PowerShell, macOS: Терминал):

```bash
python --version
```

Должно быть `Python 3.11` или выше. На macOS команда может называться `python3`. Тогда
и дальше везде пишите `python3` вместо `python`.

### Шаг 2. Скачайте проект

Код лежит в ветке `claude/kind-keller-5z0ms3` репозитория.

С Git:

```bash
git clone -b claude/kind-keller-5z0ms3 https://github.com/optimazer3/nadin-sbor.git
```

```bash
cd nadin-sbor
```

Без Git: откройте репозиторий на GitHub, слева вверху переключите ветку на
`claude/kind-keller-5z0ms3`, нажмите **Code → Download ZIP**, распакуйте архив и откройте
терминал в распакованной папке.

### Шаг 3. Создайте Telegram-бота

1. Откройте в Telegram [@BotFather](https://t.me/BotFather) и отправьте `/newbot`.
2. Введите название бота (любое, например «Задачи команды»).
3. Введите username. Он должен заканчиваться на `bot`, например `nadin_tasks_bot`.
4. BotFather пришлёт токен вида `1234567890:AAH...`. Это **`BOT_TOKEN`**.

### Шаг 4. Настройте Supabase (база данных)

**4.1. Создайте проект.** Зарегистрируйтесь на [supabase.com](https://supabase.com) и нажмите
**New project**. Укажите название, придумайте пароль базы (сохраните его, хотя боту он не нужен)
и выберите регион, например *Central EU (Frankfurt)*. Нажмите **Create new project** и подождите
1–2 минуты, пока проект создаётся.

**4.2. Создайте таблицу задач.** В левом меню откройте **SQL Editor** и нажмите **New query**.
Скопируйте всё содержимое файла [`supabase/schema.sql`](supabase/schema.sql) из проекта, вставьте
и нажмите **Run**. Должно появиться *Success. No rows returned*. В разделе **Table Editor**
теперь есть таблица `tasks`.

**4.3. Адрес проекта (`SUPABASE_URL`).** Нажмите шестерёнку **Project Settings** внизу левого меню
и откройте **Data API**. Скопируйте **Project URL**, он выглядит как `https://abcdefghijkl.supabase.co`.
Тот же адрес показывается по кнопке **Connect** вверху страницы проекта.

**4.4. Секретный ключ (`SUPABASE_KEY`), он же service_role.** См. следующий раздел.

#### Где взять ключ service_role

Ключ лежит в **Project Settings → API Keys**. На этой странице две вкладки, подойдёт ключ
с любой из них:

- **Вкладка «Legacy API Keys»** (или «Legacy anon, service_role API keys»). Там два ключа:
  `anon` (`public`) и **`service_role`** (`secret`). Нажмите **Reveal** у `service_role`
  и скопируйте ключ. Это длинная строка, начинается с `eyJ...`.
- **Вкладка «API Keys»** (новый формат ключей). Ключ из блока **Secret keys** начинается
  с `sb_secret_...`. Если ключа нет, нажмите **Add new secret key**. Это замена service_role
  с теми же правами.

Брать нужно именно **секретный** ключ. Ключи `anon` и `publishable` (`sb_publishable_...`)
не подойдут: таблица закрыта от публичного доступа (RLS), и с публичным ключом бот не сможет
сохранять задачи. Если вставить публичный ключ по ошибке, бот при запуске так и скажет.

> 🔒 **Секретный ключ даёт полный доступ к вашей базе.** Храните его только в файле `.env`
> на своём компьютере. Не отправляйте в чаты, не публикуйте и не загружайте на GitHub
> (файл `.env` уже исключён из Git через `.gitignore`). Если ключ утёк, создайте новый на той
> же странице, а старый отзовите.

### Шаг 5. Получите ключ AssemblyAI (распознавание речи)

Зарегистрируйтесь на [assemblyai.com](https://www.assemblyai.com) и откройте **Dashboard →
API Keys**. Скопируйте ключ: это **`ASSEMBLYAI_API_KEY`**. Если голосовые не распознаются,
проверьте баланс в разделе Billing.

### Шаг 6. Получите ключ Polza AI (нейросеть)

1. Зарегистрируйтесь на [polza.ai](https://polza.ai) и пополните баланс.
2. В личном кабинете создайте API-ключ. Это **`LLM_API_KEY`**.
3. В каталоге моделей выберите модель ChatGPT (например, GPT-4.1 mini) и скопируйте её ID
   точно как написано, например `openai/gpt-4.1-mini`. Это **`LLM_MODEL`**.
4. В документации Polza найдите адрес OpenAI-совместимого API. В проекте по умолчанию указан
   `https://api.polza.ai/api/v1`. Если в документации адрес другой, впишите его в **`LLM_BASE_URL`**.

Бот обращается к нейросети в стандартном формате OpenAI (Chat Completions). Поэтому вместо Polza
можно подставить любой совместимый сервис: достаточно поменять эти три строки.

### Шаг 7. Установите зависимости

В терминале, в папке проекта, создайте виртуальное окружение:

```bash
python -m venv .venv
```

Активируйте его. **Windows (PowerShell):**

```bash
.venv\Scripts\Activate.ps1
```

Если PowerShell ругается на политику выполнения скриптов, один раз выполните команду ниже
и снова активируйте окружение:

```bash
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

**macOS / Linux:**

```bash
source .venv/bin/activate
```

После активации в начале строки терминала появится `(.venv)`. Установите библиотеки:

```bash
pip install -r requirements.txt
```

### Шаг 8. Заполните файл `.env`

Скопируйте пример. **Windows:**

```bash
copy .env.example .env
```

**macOS / Linux:**

```bash
cp .env.example .env
```

Команда создаёт файл с правильным именем `.env`. Откройте его в любом текстовом редакторе
(Блокнот, TextEdit, VS Code) и впишите значения из блокнота.

> **Windows: файл получился `.env.txt`.** Блокнот сам дописывает `.txt`, а Проводник прячет
> расширения, поэтому файл выглядит как `.env`, хотя на самом деле это `.env.txt`.
> Бот понимает и такой файл (в терминале появится предупреждение), но лучше переименовать.
> Есть три способа:
>
> 1. **Командой** в PowerShell в папке проекта:
>    ```bash
>    Rename-Item .env.txt .env
>    ```
> 2. **В Проводнике:** включите показ расширений. В Windows 11 это **Вид → Показать →
>    Расширения имён файлов**, в Windows 10 — вкладка **Вид → галочка «Расширения имён файлов»**.
>    Затем переименуйте файл в `.env` и согласитесь на смену расширения.
> 3. **При сохранении в Блокноте:** «Файл → Сохранить как», в поле «Тип файла» выберите
>    **«Все файлы (\*.\*)»**, имя `.env`, кодировка **UTF-8**.
>
> Проверить имя можно командой `Get-ChildItem -Force .env*`: в списке должен быть просто `.env`.

Что вписать:

```ini
BOT_TOKEN=1234567890:AAH...
ADMIN_IDS=0
SUPABASE_URL=https://abcdefghijkl.supabase.co
SUPABASE_KEY=eyJ...
ASSEMBLYAI_API_KEY=...
LLM_API_KEY=...
LLM_BASE_URL=https://api.polza.ai/api/v1
LLM_MODEL=openai/gpt-4.1-mini
TEAM_MEMBERS=Иван,Мария,Алексей
PROXY_URL=socks5://127.0.0.1:10808
```

- `ADMIN_IDS` пока оставьте `0`: свой ID узнаете на шаге 10.
- `PROXY_URL` — адрес прокси Happ, о нём следующий шаг.
- `TEAM_MEMBERS` — имена сотрудников через запятую. По ним бот понимает, что «Ване» — это «Иван»,
  и правильно записывает имена.
- Остальные строки можно не трогать. Список по умолчанию приходит в понедельник в 10:00
  по Москве (`TIMEZONE`, `REMINDER_DAY`, `REMINDER_TIME`). Потом время можно поменять голосом.

### Шаг 9. Прокси: подключение через Happ

Из России Telegram API заблокирован, поэтому боту нужен прокси. Бот подключается к Telegram
через Happ, который уже стоит у вас на компьютере. Так же через Happ идут AssemblyAI и Supabase.
Polza AI — российский сервис, к нему бот обращается напрямую.

**9.1. Включите Happ** и подключитесь к серверу, как обычно. Happ должен быть включён всё время,
пока работает бот.

**9.2. Узнайте порт локального прокси Happ.** Happ поднимает на компьютере прокси-сервер
по адресу `127.0.0.1` и какому-то порту. Найдите порт в настройках Happ: пункт может называться
«Порт», «SOCKS-порт», «HTTP-порт», «Mixed port» или «Локальный прокси». Частые значения:
`10808` (SOCKS5) и `10809` (HTTP).

Если не нашли порт в настройках, его можно узнать командой в PowerShell. Она покажет порты,
которые слушает Happ:

```bash
Get-NetTCPConnection -State Listen | Where-Object { (Get-Process -Id $_.OwningProcess).ProcessName -match 'happ|xray|sing' } | Select-Object LocalAddress, LocalPort, @{n='Process';e={(Get-Process -Id $_.OwningProcess).ProcessName}}
```

Проверить, что порт открыт (в ответе должно быть `TcpTestSucceeded : True`):

```bash
Test-NetConnection 127.0.0.1 -Port 10808
```

**9.3. Впишите прокси в `.env`:**

```ini
PROXY_URL=socks5://127.0.0.1:10808
```

Подставьте свой порт. Если в Happ указан HTTP-порт, пишите `http://127.0.0.1:10809`.
Подойдёт любой из двух вариантов, SOCKS5 предпочтительнее.

- **Если в Happ включён режим TUN** (VPN для всего компьютера), прокси указывать не нужно:
  оставьте `PROXY_URL=` пустым, весь трафик и так идёт через Happ.
- Режим «системный прокси» в Happ сам по себе боту не поможет: программы на Python его не
  используют. Нужно указать порт в `PROXY_URL`.
- Чтобы пустить через прокси и нейросеть, допишите `PROXY_SERVICES=telegram,assemblyai,supabase,llm`.

При запуске бот напишет в терминале, через какой прокси подключается. Если прокси не отвечает,
бот сразу скажет об этом и подскажет, что проверить.

### Шаг 10. Первый запуск и ваш Telegram ID

Запустите бота (окружение `.venv` должно быть активно):

```bash
python -m bot
```

Если всё настроено, в терминале появятся строки:

```
Прокси socks5://127.0.0.1:10808 для: assemblyai, supabase, telegram
Telegram: бот @nadin_tasks_bot
Supabase: таблица tasks доступна
AssemblyAI: ключ принят
Нейросеть: модель openai/gpt-4.1-mini через https://api.polza.ai/api/v1
Еженедельный список: каждый понедельник в 10:00, следующая отправка 2026-11-09 10:00:00+03:00
Бот запущен. Напишите ему /start в Telegram. Остановить — Ctrl+C
```

Найдите своего бота в Telegram и отправьте `/start`. Бот ответит «⛔ Этот бот работает только
для руководителя. Ваш Telegram ID: 123456789». Дальше:

1. Остановите бота в терминале клавишами `Ctrl+C`.
2. Впишите ID в `.env`: `ADMIN_IDS=123456789`. Если доступ нужен нескольким людям, перечислите
   ID через запятую.
3. Запустите бота снова: `python -m bot`.

### Шаг 11. Проверьте, что всё работает

1. Отправьте боту `/start`. Появится короткая инструкция и кнопка «Список задач» внизу.
2. Нажмите микрофон и скажите: *«Ивану подготовить отчёт по продажам до пятницы»*. Бот покажет,
   как понял. Скажите *«да»*.
3. Бот напишет «Готово.» и пришлёт список, где задача стоит под номером 1.
4. Скажите *«задача 1 в работу»*, затем *«да»*. Статус поменяется.
5. В Supabase в **Table Editor → tasks** появится строка с задачей.
6. Скажите *«задача 1 выполнена»*, затем *«да»* — задача уйдёт из списка.

Чтобы проверить еженедельный список, не дожидаясь понедельника, скажите боту, например,
*«присылай список по пятницам в 15:42»* (сегодняшний день и время через 2–3 минуты), ответьте «да»
и дождитесь сообщения. Потом скажите *«присылай список по понедельникам в 10 утра»*.

### Как запускать в следующий раз: двойным щелчком (Windows)

Включите Happ и дважды щёлкните файл **`start_bot.bat`** в папке проекта. Откроется окно, и бот
запустится. Окно не закрывайте, пока бот нужен. Закроете окно — бот остановится.

Что делает `start_bot.bat`:

- находит Python (окружение `.venv` проекта, если оно есть, иначе установленный в системе);
- при первом запуске или после обновления сам ставит недостающие библиотеки;
- если бот остановился из-за ошибки, оставляет окно открытым с причиной. Исправьте
  её и нажмите любую клавишу: бот запустится снова.

**Ярлык на рабочий стол.** Щёлкните `start_bot.bat` правой кнопкой мыши → **Показать
дополнительные параметры** (в Windows 11) → **Отправить → Рабочий стол (создать ярлык)**.
Ярлык можно переименовать, например в «Бот задач».

**Автозапуск при включении компьютера.** Нажмите `Win + R`, введите `shell:startup` и нажмите
Enter. Откроется папка автозагрузки: скопируйте туда ярлык `start_bot.bat`. В настройках Happ
включите автозапуск и автоподключение. Тогда после включения компьютера бот запустится сам,
и напоминание в понедельник не пропадёт.

Без `.bat` (Windows, macOS, Linux): откройте терминал в папке проекта, активируйте окружение
(шаг 7) и выполните `python -m bot`. Остановить бота: `Ctrl+C`.

Если Happ отключится, пока бот работает, бот не упадёт. Он будет пытаться переподключиться
и сам продолжит работу, когда Happ снова подключится.

> ⚠️ Бот работает, пока открыт терминал и включён компьютер. Напоминание в понедельник
> в 10:00 придёт, только если бот в это время запущен. Если компьютер проснётся позже (в течение
> 6 часов), список отправится сразу после пробуждения. Чтобы бот работал всегда, его нужно
> перенести на сервер.

### Если что-то не работает

| Что видно | Что сделать |
|---|---|
| `Не найден файл .env в папке …` | Файл не создан или бот запущен не из папки проекта. Перейдите в папку проекта (`cd …`) и создайте `.env` (шаг 8) |
| `Файл .env не найден, читаю настройки из .env.txt` | Это предупреждение, бот работает. Чтобы оно пропало, переименуйте файл в `.env` (шаг 8) |
| `Ошибка в настройках (.env): Не задана переменная …` | Впишите эту переменную в `.env` |
| `SUPABASE_KEY: это публичный ключ …` | Вставлен ключ anon / publishable, нужен service_role или `sb_secret_…` (см. шаг 4) |
| `Telegram не принял BOT_TOKEN` | Проверьте токен от @BotFather, без пробелов и кавычек |
| `Нет связи с Telegram … включите Happ и укажите PROXY_URL` | Прокси не задан, а Telegram заблокирован. Настройте прокси (шаг 9) |
| `Не удалось подключиться к Telegram через прокси … Couldn't connect to proxy` | Happ выключен или порт неверный. Включите Happ и сверьте порт (шаг 9.2) |
| `Не удалось подключиться к Telegram через прокси …` (другая ошибка) | Happ включён, но сервер в нём не работает. Переподключитесь или выберите другой сервер в Happ |
| `PROXY_URL: тип «…» не поддерживается` | В `PROXY_URL` нужен адрес локального прокси (`socks5://127.0.0.1:порт`), а не ссылка на сервер `vless://…` из подписки |
| `AssemblyAI недоступен — голосовые распознаваться не будут` | Текстом бот работает. Проверьте `ASSEMBLYAI_API_KEY`, баланс и что `assemblyai` есть в `PROXY_SERVICES` |
| `Supabase не принял ключ (Invalid API key)` | Ключ неверный. Бот покажет начало и конец ключа из `.env`: сверьте их с ключом в Supabase. Скопируйте ключ заново кнопкой Copy, вставьте одной строкой без кавычек. Не помогло — возьмите ключ с другой вкладки (`sb_secret_…` вместо `eyJ…` или наоборот) |
| `SUPABASE_KEY от другого проекта` / `повреждён` / `не похож на ключ` / `в скрытом виде` | Ключ взят не из того проекта, скопирован не целиком, это не тот ключ (JWT Secret, пароль базы) или скопированы точки вместо ключа. Скопируйте service_role или Secret key кнопкой Copy (шаг 4.4) |
| `Supabase: таблицы tasks нет` | Выполните `supabase/schema.sql` в SQL Editor (шаг 4.2) |
| `TelegramConflictError` | Бот уже запущен в другом окне или на другом компьютере. Оставьте одну копию |
| Бот отвечает «⛔ … только для руководителя» | Ваш ID не вписан в `ADMIN_IDS` (шаг 10) |
| «😕 Не получилось распознать голосовое: AssemblyAI 401» | Неверный `ASSEMBLYAI_API_KEY` или закончился баланс AssemblyAI |
| «⚠️ Автоматический разбор сейчас недоступен…» | Не работает нейросеть. Причина написана в терминале в строке `Не удалось разобрать задачу через нейросеть: …`: неверный ключ, неверный ID модели или адрес, закончился баланс Polza |
| `ModuleNotFoundError` | Не активировано окружение `.venv` или не выполнен `pip install -r requirements.txt` |

## Как пользоваться

Нажмите на микрофон внизу и скажите, что нужно. Бот коротко переспросит. Скажите «да»
(или «верно», «сохрани») — бот выполнит, напишет «Готово.» и пришлёт обновлённый список.
Скажите «нет» — ничего не изменится. Можно и нажать кнопку «Да» / «Нет».

| Что нужно | Как сказать |
|---|---|
| Новая задача | «Ивану подготовить отчёт до пятницы», «Марии обновить прайс к среде» |
| Задача сделана | «задача 5 выполнена» — задача уйдёт из списка |
| Другой статус | «задача 5 в работу», «задачу 5 на паузу», «отмени задачу 5» |
| Перенести срок | «перенеси задачу 5 на пятницу», «убери срок у задачи 5» |
| Сменить исполнителя | «отдай задачу 5 Алексею» |
| Изменить текст | «в задаче 5 напиши: подготовить квартальный отчёт» |
| Удалить | «удали задачу 5» |
| Посмотреть | «покажи список», «покажи задачи Марии», «покажи выполненные», «открой задачу 5» |
| Когда присылать список | «присылай список по пятницам в 9 утра», «список в понедельник в 8:30» |

- Номера — те, что в последнем показанном списке. После изменения бот присылает новый список,
  и номера снова идут по порядку.
- Чтобы задачи одного человека не «двоились», укажите в `TEAM_MEMBERS` полные ФИО: тогда
  «Ивану», «Ване» и «Петрову» бот запишет как «Иван Петров».
- Задачу можно назвать по номеру, по смыслу («задача про прайс») или по исполнителю. После
  «открой задачу 5» можно говорить просто «удали её» или «перенеси её на завтра».
- В одном голосовом можно дать несколько команд: *«отчёт готов, задачу 7 перенеси на среду
  и Маше позвонить клиенту завтра»*.
- «Отмени задачу» ставит статус «Отменена», «удали» удаляет совсем.
- Новое время списка бот запоминает в файле `data/schedule.json`. Значения `REMINDER_DAY` и
  `REMINDER_TIME` в `.env` — это время по умолчанию, пока его не меняли голосом.

## Как это устроено

```
bot/
  main.py               запуск и проверки: Telegram, Supabase, планировщик
  config.py             настройки из .env
  handlers/
    common.py           /start — единственное сообщение с пояснениями
    create.py           голос/текст → команда → «Я правильно понял?» → «да» → выполнение
    tasks.py            кнопка «Список задач»
  services/
    transcriber.py      AssemblyAI: загрузка аудио и распознавание
    task_parser.py      нейросеть (Polza AI / OpenAI-совместимый API): текст → действия в JSON
  commands.py           выполнение подтверждённых команд: создать, изменить, удалить
  focus.py              какая задача открыта последней (для «удали её»)
  numbering.py          номера задач по порядку (1, 2, 3…), как их видел руководитель
  team.py               имена: «Ваня», «Иван», «Петров» → одно ФИО из TEAM_MEMBERS
  repository.py         работа с таблицей tasks в Supabase
  tasklist.py           список задач на контроле: загрузка, нумерация, текст
  scheduler.py          еженедельная отправка списка, смена дня и времени (APScheduler)
  proxy.py              прокси (Happ и др.) для Telegram, AssemblyAI, Supabase
  views.py, keyboards.py  тексты сообщений и две кнопки
  dates.py              разбор и форматирование дат
supabase/schema.sql     схема базы
start_bot.bat           запуск двойным щелчком в Windows
tests/                  тесты
```

- **Распознавание.** Аудио загружается в AssemblyAI, язык `ru`. Модель распознавания можно задать
  в `ASSEMBLYAI_SPEECH_MODEL`. Если оставить пустым, AssemblyAI выберет модель по умолчанию.
- **Разбор сообщения.** Нейросеть получает текст, список команды, календарь на три недели вперёд
  (чтобы «до пятницы» превращалось в точную дату), текущие задачи и последние 20 закрытых
  (чтобы найти, о какой задаче речь). В ответ она присылает JSON со списком действий: создать,
  изменить, удалить, показать. Бот проверяет ответ: номера задач, которых нет в базе, отбрасываются,
  а вместо них бот переспрашивает. Бот просит режим JSON (`response_format: json_object`). Если модель или
  сервис такой режим не поддерживает, бот переспрашивает без него и сам достаёт JSON из ответа.
- **Если нейросеть недоступна,** бот всё равно предложит сохранить задачу: текст целиком станет
  формулировкой, а исполнителя и срок можно будет сказать потом голосом.
- **Черновики** (ещё не подтверждённые задачи) хранятся в памяти бота и теряются при перезапуске.
  Сохранённые задачи хранятся в Supabase.
